# 新服务器部署测试清单（来客客服二开版）

> **首次安装（分步图文式）**：见同目录 **[来客客服系统安装教程.md](./来客客服系统安装教程.md)**（替代旧版 annie 网页安装向导；本包已禁用 `install.php`）。  
> 适用：已完成二维码渠道、IP 黑名单、扫码欢迎语、数据中心、员工管理增强、富媒体快捷回复、三端 UI 改版的当前代码树。  
> **不使用** `install.php`（已禁用）；采用宝塔 + 手工配置 + SQL 导入。  
> 代码根目录下文记为 **`$ROOT`**（含 `public/`、`application/`、`ymwl_pusher/`、`config/` 等）。  
> **目录说明**：`deploy/`、`docs/` 已与网站代码放在**同一项目根目录**（与 `public/`、`application/` 同级），压缩上传时**打整个项目文件夹**即可带上脚本与文档。执行脚本时若不在项目根目录，可通过 **`export PROJECT_ROOT=/实际路径`** 指定。

---

## 一、服务器环境要求

| 项 | 建议 |
|----|------|
| 操作系统 | Linux x64（宝塔常用 CentOS 7+/Ubuntu 20+） |
| Web 服务 | Nginx 1.18+ |
| PHP | **7.2～7.4**（ThinkPHP 5.0.24 与依赖在 PHP 8 上易不兼容，测试环境勿盲目上 8.x） |
| PHP 扩展 | `curl`、`mbstring`、`pdo_mysql`、`json`、`fileinfo`、`openssl`、`gd`；**CLI 下** `pcntl`、`posix`（Workerman / `ymwl_pusher` 必需） |
| 数据库 | MySQL 5.7+ / MariaDB 10.x，字符集 `utf8mb4`（若库级仍为 utf8，至少保证连接与业务表不乱码） |
| Composer | 若服务器上 `vendor` 不完整，需在 `$ROOT` 执行 `composer install --no-dev`（以你方锁文件为准） |
| 进程用户 | 宝塔 PHP 与 Nginx 运行用户多为 `www`；`ymwl_pusher` 建议用同用户或具备读代码、写日志权限的用户 |

---

## 二、宝塔站点创建步骤

1. **网站** → **添加站点**  
   - 域名：测试用独立子域（见下文「测试域名建议」）。  
   - 根目录：指向 **`$ROOT/public`**（运行目录必须是 `public`）。  
2. **PHP 版本**：选择与项目兼容的版本（推荐 7.4）。  
3. **数据库**：在宝塔创建**独立测试库**与账号（见「测试数据库建议」），记下主机、库名、用户、密码。  
4. **SSL**：测试环境建议开启 Let’s Encrypt，便于验证 **HTTPS + WSS**（见后文注意事项）。  
5. **伪静态**：选择 **thinkphp**，或把本仓库 `deploy/nginx_thinkphp.conf` 中规则合并进站点配置（见下文片段）。  
6. **防跨站 open_basedir**：若开启，需把 `$ROOT` 及上传目录纳入允许路径，否则上传/缓存易失败。

---

## 三、上传代码步骤

1. 将完整项目打包上传至服务器（如 `/www/wwwroot/kf-test/`），与本地二开版本一致。  
2. 确认存在 **`$ROOT/public/index.php`**。  
   - 若仓库中未包含（常被 `.gitignore` 忽略），从**已安装环境**复制同版本 `index.php`，或参照 `public/install.php` 内生成逻辑手工创建：需包含 `APP_PATH`、`CONF_PATH`、`define('app_key'…)`、`whost`/`wport`/`ahost`/`aport` 等与 **`ymwl_pusher/config.php`** 一致的常量。  
3. 确认 **`$ROOT/ymwl_pusher/vendor`** 完整；若缺失，在 `ymwl_pusher` 目录执行 `composer install`（若该目录有 `composer.json`）或随包携带 vendor。  
4. 上传后执行权限脚本（见 `deploy/fix_permissions.sh`）。

---

## 四、运行目录 `public`

- 宝塔网站「网站目录」或「运行目录」设为 **`/public`**（即文档根 = `$ROOT/public`）。  
- 禁止把文档根指到 `$ROOT`，否则 ThinkPHP 入口与静态资源路径错误。

---

## 五、ThinkPHP 伪静态

- 宝塔：**网站** → **设置** → **伪静态** → 选择 **thinkphp**。  
- 自定义 Nginx：使用仓库 `deploy/nginx_thinkphp.conf` 中 `location /` 片段（需放在 `location ~ \.php` 之前或与官方示例一致）。

## 七、需要导入的 SQL 顺序

### 7.1 全新空库（推荐测试机）

按顺序执行（在宝塔 **phpMyAdmin** 或命令行 `mysql` 中选中**测试库**后导入）：

| 顺序 | 文件 | 说明 |
|------|------|------|
| 1 | `install/data.sql` | 基础表结构及初始数据（含 `DROP TABLE`，**仅用于空库**） |
| 2 | `install/qr_channel_mvp.sql` | 二维码渠道、扫码日志、黑名单表、`visiter` 扩展字段等 |
| 3 | `install/ip_blacklist_extend.sql` | 黑名单操作人字段；若列已存在会报错，可忽略 |
| 4 | `install/scan_welcome.sql` | 商户扫码欢迎语配置、`wolive_qr_welcome_logs`；列已存在时可忽略重复报错 |
| 5 | `install/rich_reply.sql` | 富媒体快捷回复表 `wolive_rich_replies`（会 `DROP TABLE IF EXISTS`） |
| 6 | `install/rich_reply_phase2.sql` | 分类/标签等增量；若与 `rich_reply.sql` 中字段重复，报错可忽略 |

**校验（可选）**：`install/qr_channel_mvp_check.sql` — 仅 `SELECT` 检查表/列是否存在，不修改结构。

### 7.2 从正式库复制到测试机

- 用 mysqldump 全量恢复后，仅对**落后**于二开版的库执行 **4～6** 中尚未执行过的增量（或对比表结构后执行）。  
- **不要**在已有生产数据上再次执行 `install/data.sql`。

### 7.3 勿执行

- `install/uninstall.sql` — 卸载用，禁止在测试/生产误执行。

## 八、需要写权限的目录

至少保证 Web/PHP 运行用户对下列路径可写：

- **`$ROOT/runtime/`**（含 `cache`、`log`、`temp` 等子目录）  
- **`$ROOT/public/upload/`**（含 `images/`、`files/`、`voice/` 等业务子目录，运行期自动创建）  
- **`$ROOT/public/uploads/`**（部分平台/插件上传路径）  

可用 `deploy/fix_permissions.sh` 创建目录并 `chmod`/`chown`（宝塔常见 `www:www`）。

## 九、`ymwl_pusher` 启动命令

在服务器上（**项目根目录**或 `ymwl_pusher` 目录）：

```bash
cd $ROOT/ymwl_pusher
php start.php start -d    # 首次后台启动
# 或
php start.php restart -d  # 重启
php start.php status      # 查看状态
php start.php stop        # 停止
```

推荐使用仓库脚本：`bash deploy/start_pusher.sh`（见脚本说明）。

**配置一致性**：`ymwl_pusher/config.php` 中的 `$app_key`、`$app_secret`、`$app_id`、`$websocket_port`、`$api_port`、`$domain` 必须与 **`public/index.php`** 内同名常量及 Pusher 客户端使用的 `whost`/`wport` 一致。

## 十、防火墙 / 安全组端口说明

| 端口 | 协议 | 是否对公网开放 | 说明 |
|------|------|----------------|------|
| **80 / 443** | TCP | 是 | HTTP(S) 网站访问 |
| **`$websocket_port`**（默认常配置为 **9090**） | TCP | **是** | 浏览器 WebSocket 连接 Workerman；云安全组与系统防火墙均需放行 |
| **`$api_port`**（默认常配置为 **2080**） | TCP | **否** | Pusher HTTP API；**必须仅监听 `127.0.0.1`**（当前二开 `ymwl_pusher/start.php` 已设置 `$pusher->apiListen = "http://127.0.0.1:$api_port"`），**不要**在安全组放行该端口 |
| **3306** | TCP | 否（默认） | MySQL 仅内网或本机 |

自检：`bash deploy/check_env.sh` 会尝试检测 WS 与 API 监听地址。

## 十一、HTTPS 与 WebSocket 注意事项

1. **站点 HTTPS 后**，前端 Pusher 常使用 **`wss://`**：  
   - `public/index.php` 中 **`whost`** 需为 `wss://你的域名`（或按原系统约定仅主机名 + 独立端口，与前端 `connect.js`/模板一致）。  
2. **WSS 证书**：在 `ymwl_pusher/start.php` 中配置 `$ws_ssl_cert` / `$ws_ssl_pk`（宝塔证书路径示例见文件内注释），与 Nginx SSL 证书一致，避免证书链不完整导致浏览器断连。  
3. **反向代理 WebSocket（可选）**：若用 Nginx `proxy_pass` 把 `wss` 代理到本地 `9090`，则安全组可只开 443，但需在 Nginx 配 `Upgrade`/`Connection` 头；当前清单默认 **客户端直连 WS 端口** 的常见部署方式。

## 十二、测试域名建议

- 使用与生产隔离的子域，例如：`kf-test.你的主域.com`。  
- 避免与生产同域同 Cookie，减少串登录、缓存干扰。

---

## 十三、测试数据库建议

- 库名示例：`kefu_test` / `wolive_test`。  
- 账号权限：仅对该库 `ALL` 或最小必要权限；**勿**用 root 长期挂站。  
- 导入前备份空库或记录初始状态，便于回滚。

---

## 十四、正式覆盖前备份清单

在将测试环境验收结果合并到正式环境前，至少备份：

1. **代码**：整站 `$ROOT` 打包（含 `public`、`application`、`config`、`ymwl_pusher`、自定义 `public/assets` 等）。  
2. **数据库**：正式库全量 `mysqldump`（含存储过程、事件若有）。  
3. **配置**：`config/database.php`、`public/index.php`、`ymwl_pusher/config.php`、Nginx 站点配置、SSL 证书路径说明。  
4. **上传文件**：`public/upload/`、`public/uploads/`。  
5. **计划任务 / Supervisor**：若有对 `ymwl_pusher` 的守护配置，导出任务定义。

---

## 十五、正式切换步骤（摘要）

1. 维护窗口内停止正式站 `ymwl_pusher`：`php start.php stop`。  
2. 备份正式代码与数据库（见上）。  
3. 部署新代码至正式 `$ROOT`，覆盖前对比 `config` 与 `index.php` 差异。  
4. 执行**缺失的增量 SQL**（勿重复执行破坏性脚本）；或全量恢复已验证的测试库变更方案（由 DBA 评审）。  
5. 执行 `deploy/fix_permissions.sh`，`bash deploy/check_env.sh` 全绿或已知项可接受。  
6. 启动 `ymwl_pusher`：`deploy/start_pusher.sh`。  
7. 浏览器验证：总后台登录、客户 H5、客服台、消息实时性、二维码扫码、黑名单、欢迎语、富媒体发送。  
8. 监控 `runtime/log` 与 Nginx/PHP 错误日志 30～60 分钟。
